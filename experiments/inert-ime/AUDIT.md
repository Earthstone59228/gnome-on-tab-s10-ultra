# Independent dummy IME audit — final static review

Audit agent: separate from the builder; audited only after builder's initial handoff. No APK installation, settings mutation, process killing, display-service change or session restart occurred during this audit. Read-only ADB pulled matching framework jars and checked the missing-package command result. Private binary evidence stays outside the public repository.

## Verdict

The APK's design is suitable for a bounded Android-only admission/rebind/restore test with real SurfaceFlinger and HWC running. This is not approval for live GNOME/SF-off deployment. The final split APK-only/admission/integration scripts were independently re-reviewed. All found code blockers below are corrected. Runtime admission remains unperformed; no review/approval markers were created and nothing was deployed.

The dummy IME mitigates a particular Android handwriting crash trigger. It does not cure GNOME capture memory growth; the parent independently measured rapid compositor RSS growth and restored the software recorder.

## Defects found independently and sent to builder

1. **High: pre-SF abort discarded automatic recovery after restore failure.** Original stage `abort_before_sf` ignored settings/IME restore status, killed watchdog and removed phase. A successful dummy selection followed by failed binding admission and failed original restore could leave Android unable to type, without automatic recovery. Builder added bounded retries and retains watchdog/phase on failure. Subsequently extended the same discipline to early post-SF and normal restoration.
2. **High: settings readback was insufficient to prove original keyboard restoration.** Original helper removed originals on settings-byte verification without checking original current bound service. Builder added literal selected/current original component, main connection and non-null invoker checks across consecutive samples.
3. **Medium: fresh installation could never pass package probe.** Under `set -e`, `old=$(cmd package path org.fedora.sessionime)` exited on a genuinely absent package. Exact tablet read-only result: empty stdout, return 1. Builder now handles only rc1/empty as absence and rejects timeout/unexpected failures.
4. **Medium: added binding settlement allowed late observer changes after earlier settings verification.** Independent adversarial model reproduced a final restore that accepted late subtype-history mutation and deleted originals. Corrected: a second exact settings presence/value check after original binding settlement, immediately before deletion (`stage/fedora-session-ime.sh:145`). Both before-fix reproduction and after-fix rejection were observed in the host model.
5. **High validation gate: static approval must not enable untested live integration.** Original single installer installed APK and supervisor together. Parent requested split APK-only admission from launch integration, with pinned successful admission evidence required before installing integrated supervisor. Corrected: APK-only installation is separate; integration requires an exact successful runtime manifest and separate independent integration marker. Launcher and direct supervisor entry additionally verify installed APK/script hashes (`stage/install-dummy-ime.sh:7`, `stage/fedora-session-gnome-shell.sh:99`, `stage/fedora-session-ime.sh:46`).

6. **Medium fail-closed gap: command output was compared without preserving command status.** `user_zero` and the default-IME readback used command substitution inside a shell test. Expected text followed by a failed Binder command could still pass. Corrected: explicit successful capture before comparisons (`stage/fedora-session-ime.sh:18` and `:34`); independent regression cases cover activity and settings output-before-error and now fail closed.

## Exact Samsung framework evidence

Pulled from the user's running firmware, without changing device state:

- `evidence/samsung-framework.jar`: SHA-256 `35d848958c981dc72292abb0bcb35a3eecb340e06439b84b42db7114516d351a`.
- `evidence/samsung-services.jar`: SHA-256 `d3f0b96298170954592e43c96f3f2bafeb632436e4be43e57b5624d23594f296`.
- Selected framework classes disassembled in `evidence/samsung-smali/`.
- SDK 37 `dexdump` extracts in `evidence/samsung-*-dexdump.txt`. Important: Samsung services uses a DEX041 container containing two logical dex sections. The installed baksmali reader listed only the first; SDK dexdump was needed to inspect WMS in the second.

Samsung `InputMethodBindingController$1.onServiceConnected` reads `InputMethodInfo.supportsStylusHandwriting()` and assigns `mSupportsStylusHw` (dexdump lines 249–259). Samsung `InputMethodManagerService` checks that flag, current invoker and stylus presence before `initializeHandwritingSpy` (smali lines 15958–16030). False metadata therefore targets the actual firmware gate, not just an upstream assumption.

The shipped `InertIme` extends public `AbstractInputMethodService`, not `InputMethodService`. Its implementation allocates no view/window, stores no InputConnection, never commits text, rejects key handling and returns unchanged-hidden for show/hide requests. Resource XML explicitly disables both handwriting flags. AAPT/signature evidence agrees with source. Samsung interface default initialization calls attachToken, start delegates to start/restart, handwriting callbacks are no-ops; wrapper dispatch does not require a cast to InputMethodService in inspected methods.

Samsung `InputMethodBindingController$1.onServiceDisconnected` clears current method/sessions and retains the existing IME token; `onBindingDied` instead unbinds the method. Ordinary process death/rebind and package update/binding death are different safety boundaries. Initial bind adds an IME window token via WMS; perform selection while SF is up and avoid package updates while GNOME owns display. Final admission now captures token/display ID before and after dummy process restart and requires equality (`stage/admit-dummy-ime.sh:56`, `:94`).

Inherited `WindowProviderService` attaches a context/listener and creates a WindowManager wrapper. It does not directly add a window or SurfaceControl. Samsung adds a **final** `AbstractInputMethodService.getInitialDisplayId` that calls WMS `getImeDisplayId` (smali lines 71–117). The server reads the existing focused DisplayContent and IME policy; no direct surface operation appears there (WMS dexdump lines 23996 onward). Context attach calls `getDisplayContentOrCreate`, finds an existing display area, then registers a listener (WMS dexdump lines 9975–10000). If the display is absent, the create branch can allocate Android display surfaces. This inherited call graph prevents a universal claim that every rebind is surface-free under every device state. Validate real on-device rebind while SF is up first; any SF-off test must use the existing supervised time limit/panic/watchdog and stable display.

## State/ordering review

The helper snapshots exact present/absent values, including empty subtype history, before enabling/selecting the dummy. It refuses stale/incomplete originals, unset default and foreground users other than 0. Kernel flock prevents concurrent helper mutation; Binder commands have timeout plus forced kill because supervisor descendants ignore TERM. Current-component fields are scoped to the bound user-0 section before installed-method listing, so advertised support of an unbound service cannot pass admission. A second admission check occurs immediately before SF stop.

Restore requires real SF and HWC running, no sfsentinel and a responsive real SF layer-list command before selecting the original. It never disables Samsung Keyboard or filters input devices. Plain restoration retains originals over zygote restart; final cleanup removes them only after verification. Settings integration still restores unrelated protective settings on IME failure. The shared restore remains an unchanged pinned baseline; it starts real display owners before invoking settings/IME restoration. New kill operations in reviewed integration target existing watchdog IDs, not broad Android process names.

Installer/rollback baseline hashes, staged SHA256SUMS, no existing owner package/helper, Android display ownership and backup guards were reviewed. Supervisor replacement uses preserved old-file metadata and rename; package install occurs without selecting dummy. Partial failures keep backups. Rollback requires Android display ownership, restores original IME first, reinstates baseline scripts and uninstalls only the fresh package. Final split review: stage 1 requires its own admission-review marker and changes only package installation; stage 2 checks installed APK against the fresh-install receipt and reviewed manifest, switches/snapshots through the helper, kills only a numeric exact dummy PID validated twice by UID/cmdline, and requires three NEW PID + current remote Binder identity samples. It also requires unchanged system_server PID and token/display. EXIT/INT/TERM/HUP cleanup restores the original before generating ADMISSION_PASSED; failed restoration retains originals and starts an IME-only retry worker. Stage 3 installs no package and performs no keyboard switch; it requires separately reviewed integration plus the identical admitted manifest, verifies device baselines and installed APK, and installs a future-launch hash gate. Rollback now supports APK-only and failed admission as well as integrated installation, restores originals before uninstall, validates package hash against fresh-install receipt, invalidates future admission and retains evidence. No new script starts/stops SF/HWC/zygote outside the inherited session restore flow.

## Checks and limits

Builder's host shell model passed its original five scenarios; subsequent nine scenarios include wrong original binding and transient/permanent abort recovery. Independent `audit_checks.py` tests the real staged helper against wrong foreground user, wrong dump user, disconnected binding, null invoker, visible IME and installed-method-only spoof. All six failed closed. Its late-observer case reproduced defect 4 before correction; all nine independent cases now pass, including late observer and two output-before-error cases. Builder’s nine scenarios also pass after final changes. APK v3 signature/resource checks and staged hash checks passed. Host models establish state handling and parser rejection, not real Samsung service creation, observer timing, low-memory rebind or keyboard usability.

- All nine staged artifact hashes, shell syntax, nested supervisor bash syntax, both host test suites and APK v3 signature verification passed. The shared restore remains byte-identical to baseline.
- No `APK_ADMISSION_REVIEWED`, `INTEGRATION_REVIEWED` or `AUDIT_APPROVED` marker exists. The report supports creating **only** the APK/admission review marker for a future supervised Android/SF-UP test of exactly this snapshot. It does not support enabling integration now.

Remaining required evidence before a live GNOME test: actual Android-only service creation, unchanged current token across dummy process death/rebind, live Binder PID proof, zero dummy UI/window activity, unchanged framework PID, exact secure-state restoration, usable original Samsung keyboard, and review of on-device errors during admission. Even successful SF-UP admission cannot prove every future SF-off event; package-update/binding-death, missing-display, framework-restart and other Android surface creation paths remain outside this mitigation. A later SF-off test must be short and supervised under the existing panic/watchdog/restore harness. The current user-away GNOME session must not be restarted for it.

Admission’s traps cannot catch SIGKILL, host disappearance or power loss; originals are durable before selection and rollback/recovery are provided, but operator supervision is still required. Root/adb access must remain available during admission. Hash markers enforce version/evidence consistency within the trusted staging workflow; they are not a cryptographic boundary against an attacker already able to write root-owned staging/runtime files.

## Optional v3 screen recorder source review

Compared `gnome-hw-recording/resource-src-v3/screencastService.js` directly against `screencastService.original.js`: only one added pipeline and support for its pipewireOptions differ. The pipeline requests DMA_DRM DMABuf capture with 4–8 producer buffers, a leaky two-buffer raw queue, V4L2 DMABuf input import, encoded H.264 parsing and fragmented MP4. It adds no Android service changes and leaves upstream negotiation/error/crash-blocklist/fallback handling intact. No obvious dangerous static interaction was found. Vendor DMA import/fence/lifetime behavior required actual testing; parent reports autonomous idle/motion tests, including 20 seconds motion, with plateauing compositor memory and successful start/stop/stock rollback. This corroborates the scoped path; I did not independently run those device tests. Host static review is not a claim of all-resolution/framerate or indefinite-runtime safety.

Follow-up portability check: after the recorder installer exposed an Android mksh default `hash` alias, a read-only Android alias-name check covered all keyboard helper names (`log`, `fail`, `s`, `c`, readiness/binding/restore helpers and supervisor functions). None collided with an existing alias in the checked Android shell. This is a shell portability check, not an IME runtime admission.
